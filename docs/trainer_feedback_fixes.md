# v1.3.1 Trainer Feedback Verification

This document maps every trainer/automated-grader observation to executable code, a regression test, and runtime evidence. The canonical machine-readable source index is `EVALUATION.json`; the runtime index generated by CI is `evidence/runtime_grader_probe.json`.

## 1. Declared libraries are genuinely used

### Uvicorn

`src/contractguard/server.py` imports `uvicorn` and calls `uvicorn.run(...)` as the actual FastAPI process runner. `test_uvicorn_runner_is_invoked_not_only_declared` monkeypatches `uvicorn.run` and proves `server.main()` invokes it with the configured host and port.

### ipykernel

`scripts/build_executed_notebook.py` imports `make_ipkernel_cmd` from `ipykernel.kernelspec`, calls `make_ipkernel_cmd()`, records the returned launch command in notebook metadata, and prints the command in the executed notebook environment cell. This is execution-related use, not a requirements-only declaration.

## 2. Guardrails enforce behavior in executable code

`InputSecurityAgent.run()` calls:

```python
self.input_guardrail.enforce(...)
```

`InputGuardrail.enforce()` calls the injection detector and raises `GuardrailViolation` on a detected attack. The graph's conditional router sends `input_blocked=True` directly to the terminal `blocked` node. The attack test and runtime evidence assert that zero tools executed.

`OutputGuardianAgent.run()` calls `OutputGuardrail.enforce()` before artifact storage. That guardrail performs PII masking, secret-pattern filtering, and strict `AuditReport.model_validate(...)` schema enforcement. Invalid output routes through a bounded revision loop instead of being stored.

Regression proofs:

- `tests/test_guardrails.py`
- `tests/test_trainer_fixes.py::test_guardrail_enforcement_executes_real_block`
- `tests/test_workflow.py::test_indirect_prompt_injection_is_blocked_before_tools`

Runtime proof:

- `evidence/01_prompt_injection_blocked.json`
- `evidence/05_high_risk_resumed_and_completed.json`

## 3. The workflow is a genuine branching LangGraph StateGraph

`src/contractguard/workflow.py` creates:

```python
workflow = StateGraph(AuditState)
```

and contains **five executable calls** to `workflow.add_conditional_edges(...)`:

1. input guardrail: `blocked` vs `safe`;
2. policy research: `retry` vs `success` vs `failed`;
3. quality review: `retry` vs `pass`;
4. security review: `human` vs `automatic`;
5. output guardrail: `revise` vs `valid` vs `failed`.

The graph has three bounded loop/re-entry paths:

```text
policy_research -> policy_research
quality_reviewer -> policy_research
output_guardian -> report_writer
```

The shared `AuditState` object is read and updated by nodes. Loop counters and `MAX_GRAPH_STEPS` prevent infinite execution.

Regression: `test_real_langgraph_stategraph_has_explicit_conditional_edges`.

Runtime proof: `evidence/graph_spec.json` and the repeated node path in `evidence/03_high_risk_paused_for_human.json`.

## 4. HITL pauses and resumes end-to-end

The `human_approval` node calls:

```python
decision_payload = interrupt(...)
```

The service returns while the persisted thread is `awaiting_approval`. The demonstration closes the first `ContractGuardService`, creates a fresh service against the same SQLite checkpointer, and verifies that `human_approval` is still pending.

External approval then resumes the same LangGraph thread with:

```python
self.graph.invoke(
    Command(resume=request.model_dump(mode="json")),
    config=config,
)
```

After resume, the human node returns either:

```python
Command(goto="report_writer", ...)
```

or:

```python
Command(goto="rejected", ...)
```

Regression: `tests/test_workflow.py::test_retry_pause_restart_resume_and_output_revision`.

Runtime proof:

- `evidence/03_high_risk_paused_for_human.json`
- `evidence/04_checkpoint_loaded_after_restart.json`
- `evidence/05_high_risk_resumed_and_completed.json`

## 5. Multi-agent implementation uses independent specialist objects

The repository contains ten concrete agent classes in separate modules:

1. `InputSecurityAgent`
2. `CoordinatorAgent`
3. `DocumentAnalystAgent`
4. `PolicyResearchAgent`
5. `ComplianceAnalystAgent`
6. `QualityReviewerAgent`
7. `SecurityReviewerAgent`
8. `ReportWriterAgent`
9. `OutputGuardianAgent`
10. `ArtifactStorageAgent`

`ContractGuardService._build_agents()` independently instantiates those classes. They are not one prompt that changes persona.

`BaseAgent.send()` creates a typed `AgentMessage` containing `sender`, `recipient`, `message_type`, `content`, `payload`, and `timestamp`, then appends it to shared `AuditState.agent_messages`. The executed high-risk evidence contains messages from multiple concrete specialist senders to multiple recipients.

Regression proofs:

- `test_multiple_agents_are_real_classes_in_separate_modules`
- `test_multi_agent_communication_is_typed_and_persisted`
- runtime assertions in `scripts/run_capstone_demo.py`

## 6. Automated grading receives strict JSON

`python scripts/grader_probe.py` is dependency-free and writes exactly one JSON object to stdout.

`python scripts/runtime_grader_probe.py --refresh` captures the human-readable demo output internally and also writes exactly one JSON object to stdout. On any runtime exception it still emits a parseable JSON error object before exiting non-zero.

CI validates both outputs with `python -m json.tool` and publishes/commits:

- `EVALUATION.json`
- `evidence/runtime_grader_probe.json`

This removes mixed stdout as a repository-side cause of `Expecting value: line 1 column 1` parsing failures.
